The home screen has four parts, from top to bottom: the **header**, the **log**, the
**suggestion strip**, and the **prompt** (`$`), with the **key bar** below it while you type.

## The prompt

Type a command, or any part of an app name, and press Enter.

- **Commands** come first: `help` lists them all, grouped. See the [command reference](/reference/commands/).
- **Aliases** you defined with `alias m = open maps` expand before anything else.
- **Script commands** are scripts marked [`@command`](/scripting/overview/#command-scripts). They run by name with arguments.
- **Anything else is an app name.** Enter launches the best match, which is the highlighted first
  suggestion chip. More precisely:
  - an exact label match launches;
  - if only one app matches, it launches (`launch.single`);
  - if the top match starts with what you typed, it launches (`launch.top`);
  - otherwise you get a grid of up to 12 matching apps to tap.
- **Instant launch** (`launch.instant`, default `all`): as soon as what you typed
  can only mean one app, it opens without Enter. With apps *Calculator* and *Calendar*, `calc` opens Calculator
  and `cale` opens Calendar. The same app in several profiles counts as one match (the copy you use most opens),
  unless two of those profiles are on: with the work profile running, `gm` opens nothing and
  suggests both Gmails (Gmail and Gmail [W]) for you to pick.
  `launch.instant all` also runs commands that take no arguments, and aliases, this way (`setti`
  opens settings; `contacts` waits for Enter so you can still type `contacts bob`), and makes a
  tapped history line run immediately. A line with arguments runs too once there is
  nothing left to choose, whether typed, picked from the suggestions or tapped in the log: `torch on`, `dnd off`, `ring silent`, `media pause`. `torch o`, `volume up`
  (a number could go there instead) and `apps work` (`-l` could follow) wait for Enter.
  Sensitive commands never run without Enter: `call`, `sms`,
  `uninstall`, `work`, `private`, `clear`, `restart`, `lock`, `script`, `config`, `alias` and similar.
  Calls always open the dialer, so you confirm there. `launch.instant-letters` (default 2) is how many
  letters to type first; `launch.instant off` turns it off.
- A mistyped command gets a tappable **"did you mean"** that puts the corrected command in the prompt.
- `= <expression>` is a [calculator and unit converter](/guides/web-and-calculator/).

### Suggestions

The strip is hidden on an idle home screen and appears while you type (the on-screen keyboard is
up, or there is text in the prompt); `suggestions.auto off` keeps it always visible.

The strip above the prompt changes as you type:

- **Empty prompt**: your [pinned favourites](/guides/apps/#favourites) first, then your most-used apps, ranked
  by frecency (how often and how recently you opened them).
  Off by default; turn it on with `config set suggestions.idle on`.
- **First word**: up to three matching commands, aliases or script commands, plus matching apps.
  When Enter would launch an app, that app is the first, highlighted chip, so Enter, Tab and the
  highlight always agree.
- **Arguments**: almost every command completes what comes next.
  - App names after `open`, `info`, `hide`, `rename`, `pin`, `shortcuts`, `notifs mute` and
    similar. After `open maps:` you get that app's shortcuts.
  - Contacts after `call`, `sms` and `contacts`: favourites first, then everyone, even before you
    type a name. A contact with several numbers shows one row per number, and choosing one fills in
    that number.
  - Script names after `script run|edit|…`, keys and values after `config`, theme and font names,
    feeds after `feed read|rm|…`, aliases after `unalias`, status lines after `status clear`.
  - The options a command's usage lists, such as `apps work|personal|…`, `clear history|all`,
    `torch on|off` or `dnd alarms`.
  - Your earlier commands that start with what you typed, so `search ` or `yt ` offers your past
    queries.

Command chips start with `$` (`$ maps`), app chips show the app name, and a ✕ at the end of the
prompt clears it. Tap a chip to use it. Tab (on the key bar or a hardware keyboard) takes the first one. The number
of chips is `suggestions.max` (default 30).

By default (`suggestions.style list`) the suggestions are a **list** stacked directly above the
prompt instead of chips: the best match sits at the bottom, nearest your thumb, highlighted with
a ⏎ because it is what Enter and Tab act on. Command rows show `$ name` and the command's short
description, cut to one line (`suggestions.wrap on` shows all of it, over more lines); app rows show the profile tag. The list takes at most about 40% of the screen, and
never more than the room above the prompt, so the prompt stays in view; it scrolls beyond that. Long-press an app row for its actions. `config set suggestions.style chips`
brings back the chip strip (`suggestions.rows` applies to chips only). In both styles each app's
icon sits in front of its name, and commands get a terminal icon in the same place, so every name
lines up; work and private apps carry the system's profile badge. **Show app icons**
(`suggestions.icons`) turns the icons off.

### App selector

Turn on **Show the app selector** (Settings → App selector, or `config set selector.rail on`) and, while
the keyboard is down, a slim handle sits on an edge of the log. It opens an **app selector** that you
drive with one thumb, no typing needed. **Edge** puts it on the right (the default) or the left
(`selector.side`), **Where on the edge** at the bottom (the default), middle or top
(`selector.position`), and **Length on the edge** sets how much of the edge it takes
(`selector.height`): keep it away from where you swipe back. With gesture navigation, Android lets
an app keep the back swipe off only 200 dp of an edge, so a touch starts the selector only in the
middle 200 dp of that length, where the handle is drawn; at the ends the edge swipes back as usual.
Once your thumb is down, it slides over the whole length.

- **Touch the handle's part of the edge.** Home dims, and a panel slides in on the other side of the
  screen, the whole height, listing *all* your apps in one list:
  your favourites (★), then everything alphabetically, with small section letters in the
  margin (`#` holds apps that start with a digit, a symbol or a non-Latin letter), and each app's
  icon if you turn on the selector's **Show app icons** (`selector.icons`). Its **Phone's font**
  (`selector.system-font`) shows the list and the letters in the phone's own font instead of the
  terminal font. Work and private apps carry their `[W]` / `[S]` tags, paused profiles are faded
  and hidden apps are left out. About 20 apps fit on screen at once. With the selector at the bottom of the edge (the
  default), your favourites come last, at the bottom where your thumb rests; at the middle or the
  top they come first.
- **Slide along the edge to a letter.** It goes a letter at a time, with a tick for each: every
  letter that has apps gets the same stretch of the edge, so a letter with a single app is as easy
  to land on as one with many. The letter you're on shows big in a circle beside your thumb, and the
  letters around it bulge out from the edge, clear of your thumb (the list is narrower while your
  thumb is down), so you can see which way the one you want is. The list glides to that letter's
  apps and holds still there, starting level with the circle, the first one at your thumb's height
  and the rest below it (moved up only as far as keeps them on screen), and the other letters' apps
  fade back while you slide; near the list's ends the panel moves to keep them there. **Show letters on the edge** (`selector.letters`) draws each letter
  along the edge at rest, in the middle of its stretch and in place of the handle, so you can see
  where to touch.
- **Only the letter's apps** (`selector.filter`, off unless you turn it on): the list holds just the
  letter's apps instead of the whole list at that letter, beside the circle.
- **Slide through** (`selector.browse`) set to `apps` goes through the whole list by its apps
  instead of a letter at a time. Your thumb's place on its part of the edge maps smoothly onto the
  list (its top = the first app, its bottom = the last), so small moves give fine control and a long
  slide crosses the alphabet. Every letter gets room along the edge by the square root of its number
  of apps: a letter with four times the apps gets twice the length. The app you're at sits level with
  your thumb, magnified (its neighbours a little less), and the circle shows its letter. Slide slowly
  to aim: under about 100 dp a second, the list moves one app for every 10 dp of your slide, with a
  light tick for each; speed up again and it catches up with where a fast slide would put it.
  (`selector.aim` and `selector.aim-speed`, with `config set`.)
- **Slide well off the edge, toward the panel,** and the list holds still: move up or down to pick
  an app (near the panel's top or bottom it keeps scrolling), then **lift to launch** it. A short buzz
  marks leaving the edge or coming back to it, and a lighter tick marks each app you pass. Or hold
  still on an app: its row fills, and when it's full, after most of a second, the app launches
  without your lifting. Moving clears the fill. An app's actions (the same sheet as long-pressing
  it) are in the list you leave open, or, if you turn on [actions while picking](#app-actions-while-picking),
  under your thumb as you pick. To back out without launching, slide back onto the edge before you lift.
- **Lift on the edge** and the panel stays open as a normal list (with **Only the letter's apps**,
  just those), a tapped letter's apps still beside it. It widens almost to the edge, so your thumb
  reaches every row, the top ones too, from its own side: fling it, tap an app to launch, long-press for
  its actions, or slide the edge again.
  A tap elsewhere, Back, or 4 idle seconds close it.

Android lets an app keep at most 200dp of each screen edge from the back gesture, so only the
middle 200dp of the edge does; above and below it a swipe in from the edge still goes back.

#### App actions while picking

Off unless you turn it on with `config set selector.actions far-side` (and `off` to turn it back
off); it isn't in Settings. It changes what lifting does once you've slid off the edge onto the
list. The third of the list farthest from your thumb's edge becomes its **far side**: slide on into
it and a short buzz marks it, the row you're on says **⋯ Actions**, and lifting there opens that
app's actions (the same sheet as long-pressing it) instead of the app. Holding still there doesn't
launch it either. Anywhere else on the list, lifting launches the app as usual. With the selector
on the left edge it's mirrored: the list opens on the right, and its far side is its right-hand
third.

## The log

The log is split into **groups**, with a gap above each one (`log.spacing`, 0–40 dp). A group is a
command you typed and its output (a script's lines too, when you ran it), a script's or a feed's
lines from one background run, or lines that arrived together. A line that arrives on its own more than 3 seconds after the previous one, such
as a tap launch, an app install or a notification, starts its own group. A thin coloured bar beside
each line shows where it came from: green for commands, the script colour for background output,
red for errors. Hide it with `log.gutter off`. Output older than the latest command is dimmed
(`log.dim`).

- Day separators, and right-aligned times: on each group's first line, and again when the minute
  changes (`log.time`: `groups`, the default; `commands` on the lines you type, `off` none).
- `help`, `config` and `script ls` render in two columns; `apps` is a grid of tappable chips.
- Script, feed and notification lines name their source at the end, muted (`Show HN: … · Hacker
  News`), on the first line of a run from that source; lines right under the command that ran them
  don't, since the command names it. A line's long-press shows where it came from and when, to the
  second. Lines that arrived while you were away are marked `•` under a "N new since you left"
  divider.
- **Fresh screen** (`log.fresh`, 10 minutes): come back to home after a while and it
  starts clean, so old output and app grids are not under your thumb. Nothing is deleted: tap
  "▴ N earlier lines" to bring it back. `fresh` does the same on demand (and isn't logged itself). Script lines that arrived while you were away stay visible.
- When you scroll up, a ↓ button jumps back to the newest lines. Repeating a command with nothing
  printed in between (`settings`, `settings`) doesn't add another line.
- Scroll to the top to load older entries. Entries older than `log.keep-days` (60), and past the
  newest `log.keep-lines` (5000), are trimmed. Typed commands are counted apart, so ↑ history stays.
- `clear` clears the screen, `clear history` forgets the ↑ history but keeps the log, and
  `clear all` removes both.

### Searching the log

Type `/` and some words at the prompt: the log shows only the lines that have all of them, from
everything it keeps (lines a fresh screen hid too), with the words marked and each line's time.
Words are found in what a line says, in commands you typed, and in where a line came from and where
it leads: `/weather` finds the weather script's lines, `/github.com` the lines that link there.

```sh
/battery              # every line about the battery
/hacker news rust     # feed items from Hacker News that mention Rust
/@xkcd                # every line from the xkcd script
/@hackernews rust     # Rust, only in Hacker News's lines
/@scripts error       # errors from any script
```

`@` and a name keeps only the lines from there: a script, a feed or an app, as the name at the end
of its lines reads, any case and without spaces. Or a whole kind: `@commands` (what you typed and
what it printed), `@scripts`, `@feeds`, `@notifications`, `@apps` (installs and updates), `@calls`,
`@reminders`. Typing `/@` suggests them; two `@`s find lines from either.

Tap a line to see it in the log, among the lines around it. `Enter` puts the keyboard away so
more results fit; `Esc`, back or clearing the prompt ends the search. Long-press and swipes work as
they do in the log.

### Only one source's lines

Long-press a line and pick **Only xkcd** (its script, feed or app; a command line offers **Only
commands**), or type `log only xkcd` or `log only feeds`. The log then shows just those lines, new
ones as they come, with a bar above the prompt saying so. It stays, through leaving home and a
restart, until ✕ on the bar, back, `log all`, or running another command, so what you type always
shows.

### Pipes

Filter a command's output like a shell:

```sh
help | grep feed              # rows mentioning "feed" (the description column counts too)
history | tail 5              # last five commands
feed read | grep -v sponsored | head 3
contacts | count              # how many lines
config | sort
```

Filters: `grep [-v] <pattern>` (case-insensitive regex; an invalid regex is matched literally),
`head [n]`, `tail [n]` (default 10), `sort [-r]`, `uniq`, `count` (or `wc`). Error lines always come
through. Only output the command prints right away is filtered; replies that arrive later (network
requests, scripts) are written as usual. A `|` only starts a filter when a filter name follows it,
so `js a || b` and Lua code are left alone.

### Tap and long-press

**Tap** a line for its main action:

| Line | Tap does |
| --- | --- |
| A command you typed | puts it back in the prompt |
| An app line or chip | launches the app |
| A link (feed item, search, script line with a URL) | opens it |
| A phone number or contact | opens the dialer |
| A notification | opens it (or the app, if it's gone) |
| An app shortcut | starts it |
| A setup or hint line | runs its fix command |
| A script error | opens the editor at the failing line |

**Long-press** opens an action sheet with everything that applies: run again, edit in prompt, copy
output, open, share or copy a link, call, message or copy a number, launch in another profile, app
shortcuts, app info, hide, uninstall, run or edit a script, dismiss a notification or mute its app,
copy text, and delete the line, or a command with all its output: a script's lines too, which can
land later, under other lines.

### One-handed use

- **Quick actions:** tap the `$` at the start of the prompt for everything the header offers —
  settings, notifications, alarms, battery, network, unlocks, pause / resume the work or private
  profile, apps, widgets, feeds, scripts and lock, with the header's icons (battery and network
  as they are now). Any gesture can open it too (`quick`).
- **Swipe a log line:** right copies it, left deletes it (with UNDO for a few seconds).
- **Long-press output** to run or edit the command that printed it.
- **Two rows of suggestions** while typing (`suggestions.rows`).

## The header

A large clock and date, then unlocks, battery, network, next alarm, profile state and ⚙︎, shown
as icons: the battery is drawn to its charge level (green with a bolt while charging, red when
low), and the network icon shows Wi-Fi, mobile or offline. `header.icons off` brings back the
text labels (`bat`, `net`, …). Every item is tappable:

| Item | Tap | Config key |
| --- | --- | --- |
| Clock, next alarm | opens your alarms | `clock.24h`, `header.date`, `header.alarm` |
| `unlocks` | runs `unlocks 7` | `header.unlocks` |
| `bat` | battery usage | `header.battery` |
| `net` | network settings | `header.network` |
| `work` / `private` | resumes a paused profile; pausing asks for a second tap | `header.profiles` |
| ⚙︎ | the [settings screen](/guides/themes-and-settings/) | |
| Script status lines | runs that script | `header.status` |

**Auto-hide** (`header.autohide`, on by default): while you scroll back through older output the header
disappears entirely; scrolling toward the newest lines (or running a command) brings it back as one
line with the time, battery and the number of hidden status lines. Tap it or swipe down on it to expand it; pressing Home, coming back from an app or `clear`
also brings it back.

While you type (the keyboard is up, or there is text in the prompt), the header shrinks
to that one line, so the suggestions get the room. It comes back
as it was when you're done.

`header.device` adds a `kolahal@device` line. Swipe down on the header to pull down the
notification shade (a [gesture](/guides/gestures/) you can change).

To do without the header, turn off **Show the header** (`header.show`): the log takes the whole
screen. Settings then opens with `settings`, and script status lines aren't shown.

## The key bar

The bar appears only while the on-screen keyboard is up for the prompt, so an idle home screen
shows more of the log (`keybar.auto off` keeps it always visible). It sits
below the prompt, right on top of the keyboard, so the best suggestion stays just above what you type.
The ⌨ button at the right end of the prompt line turns the bar on or off (`keybar.show`, off by default); it is
green while the bar is on.
Make it and the prompt slimmer while typing with `keybar.height` (row height, 20–64 dp) and
`prompt.height` (20–72 dp), also under Settings → Typing.
`log.line-height` (Settings → Log, 22 unless you change it) sets the height of log lines: lower
for a denser log (down to as short as the text allows), higher for more room. It follows the
phone's text size, as the text does. **Taller tappable
lines** (`log.taller-taps`) makes the lines you can tap a little taller than the others, easier to
hit, and `chips.height` sets the height of suggestion and app-grid chips.

Touch keyboards lack the keys a terminal needs, so Kolahal adds a two-row bar:

```
ESC  /  -  ⇤  ↑  ⇥  ⌫
TAB  |  .  ←  ↓  →  ⏎
```

- `↑` / `↓` walk the command history; `TAB` completes; `ESC` clears the prompt; `⇤` / `⇥` jump to
  the start or end.
- Arrows and backspace repeat while held, and dragging sideways across the bar moves the cursor.
- Both rows are configurable: `keybar.row1` and `keybar.row2` take comma-separated keys from `ESC TAB UP DOWN
  LEFT RIGHT HOME END BKSP ENTER SPACE KBD`, or any literal text. `KBD` shows the soft keyboard.
  Clear **Key bar, row 2** in Settings for a single row, or hide the bar with `keybar.show off`.

```sh
config set keybar.row1 ESC,TAB,UP,DOWN,|,~,KBD
config reset keybar.row1      # back to the default row
```

## Touch

- Tap empty log space to bring up the keyboard (`keyboard.on-home on` opens it every time Home is shown).
- Pinch the log to resize the text (`font.size`, 10–24). When you let go, a toast says the new size.
- Double-tap empty log space to lock the screen. Swiping up on the prompt does nothing until you
  set it: `config set gesture.swipe-up apps` opens the app grid. See [Gestures](/guides/gestures/).

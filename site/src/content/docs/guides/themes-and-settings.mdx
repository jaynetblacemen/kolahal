### Light and dark

The phone's dark mode picks the version: dark when it is on, light when it is off, switching as
soon as the phone does. To keep the dark version whatever the phone says, turn on **Always dark**
in **Settings → Look & feel**, or:

```sh
config set theme.always-dark on
```

### Your own themes

**Settings → Look & feel → Your themes → Create a theme** opens the theme builder. It starts from
the theme in use; **Start from** copies any other theme's colours. A small home screen at the top
shows your colours as you change them. Tap a colour to change it: drag hue, saturation and
lightness, type a hex code (`#8FD18A`), or tap a swatch (the same colour from the built-in themes,
and the theme's other colours, so it is easy to match them).

The colours, from the top of the builder:

| Colour | Colours |
| --- | --- |
| Background, Surface | behind everything; chips, the key bar and raised panels |
| Text, Muted text | commands and their output; times, hints and older output |
| Accent | the prompt, `$` and highlights (Settings use it too) |
| Links, Info, Script output, Errors | links and feed items; notes from Kolahal; your scripts' lines; errors |
| Good, Warning | what scripts mark as up or done, and as a warning ([`fmt.color`](/scripting/api/#styles-fmt)); a theme made before them takes them from its personal and work colours |
| Personal apps, Work apps, Private space | apps in each profile, if you have them |

**Dark** and **Light** at the top switch which version the colours change; the preview shows that
version. A theme you made before themes had a light version looks the same in both modes until
you change its light one.

Give it a name (lowercase letters, digits and hyphens) and tap **Save and use**. It then sits with
the built-in themes in the theme strip and in `theme <name>`. Tap it under **Your themes** to change
or delete it. A light background works too: the status bar icons turn dark. Your themes are kept in
[backups](/guides/backup/).

To share a theme, open it and tap the export icon at the top: it saves the theme, as last saved,
in a `.json` file with its name and both versions. **Your themes → Import a theme** takes such a
file. The theme joins yours under the name in the file, with a number added if you already have a
different theme by that name, and is put in use.

## Fonts

```sh
font                 # list the fonts; tap one to use it
font jetbrains-mono
font import          # pick your own .ttf / .otf
font sans prompt     # the phone's own font for the prompt (or: all, off)
```

The terminal font is used everywhere the terminal draws text: the log, prompt, header,
suggestions, key bar and the script editor. Choices:

| Name | Font |
| --- | --- |
| `system` | the phone's monospace font |
| `jetbrains-mono` | [JetBrains Mono](https://www.jetbrains.com/lp/mono/) (default) |
| `fira-code` | [Fira Code](https://github.com/tonsky/FiraCode), with programming ligatures (`=>`, `!=`, …) |
| `ibm-plex-mono` | [IBM Plex Mono](https://github.com/IBM/plex) |
| `source-code-pro` | [Source Code Pro](https://github.com/adobe-fonts/source-code-pro) |
| `custom` | a font file you imported |

The bundled fonts ship in Regular and Bold under the SIL Open Font License 1.1 (licence texts are
in the app's `assets/licenses/`). `font import`, or the import card in the settings screen's font
previews, copies a `.ttf` or `.otf` (up to 10 MB) into the app and switches to `custom`; importing
again replaces it, and backups carry it. If the custom font goes missing or can't be read, the
terminal falls back to the system monospace and says so once in the log. Text size stays a separate setting: `config set font.size 16`, or pinch the log.

### The phone's font

The terminal can use the phone's own font (the one Android and its apps use,
including a font style you picked in the phone's settings) instead of a monospace one, at two levels:

| `font.sans` | What changes |
| --- | --- |
| `off` (default) | nothing: everything uses the terminal font |
| `prompt` | the prompt line, where you type |
| `all` | all of the terminal: the log, header, suggestions, key bar and prompt |

Set it with `font sans prompt` (or `all`, `off`), or under **Settings → Look & feel → Terminal**.
With `all`, a few things stay in the terminal font, because they only line up in a monospace one:
lists that line up columns (`unlocks`, `todo`, `notes`, `reminders`, `agenda`, `toggles`, `font`,
`script cat`) and the script editor. Wrapped lines and the dimmed lines under an entry still line up
with the text above them.

## Settings screen

`settings` (or `config` with no arguments, or ⚙︎ in the header) opens a Material 3 screen with
grouped lists: switches, connected button groups, sliders and theme preview cards. At the top,
**Settings**, **Scripts** and **Feeds** are three tabs: the [Scripts](/scripting/overview/#running-scripts)
and [Feeds](/guides/feeds/#feeds-screen) tabs are those screens, and `scripts` and `feeds` open
them. A search box finds any setting, feed ones included. The pages:

- **Look & feel**: theme, Always dark, font, the phone's font, text size, full screen, and your own themes.
- **Home screen**: clock, header items, widgets, and how much of the phone's wallpaper shows behind the widgets page.
- **App selector**: letters or apps as you slide, the edge it's on, where and how long, the handle or letters, only the letter's apps, icons in its list, and the phone's font.
- **Log**: times, dimming, spacing, line height, how much of the phone's wallpaper shows behind it, how long to keep the log, and a tip a day for your first two weeks.
- **Typing**: suggestions, the key bar, the prompt and the keyboard.
- **Launching & search**: instant launch, Enter, search engine.
- **Gestures**: the three [gestures](/guides/gestures/).

Below them are the widgets and the setup checklist,
[backup](/guides/backup/) (automatic backups and their folder, back up now, export and import), and **About**: this guide, the
[crash reports](/reference/privacy/#crash-reports) kept on the phone (tap one to email it to the
developer or delete it), an email to the developer, and the version.

A changed setting shows a reset icon (↺) right after its name: tap it to go back to the default. A switch is reset by switching it back.

Settings only shows what applies. A setting that another one turns off stays hidden until it is on:
the key bar's rows and height appear once the key bar is on, the custom search URL once the search
engine is `custom`, and so on. `config` reaches every setting either way.

### Seeing home while you change it

Settings that change how home looks show home while you change them, like the brightness slider
in the quick settings:

- **Drag a slider** for text size, line height, log spacing, key bar or prompt height, suggestions,
  chip height, or the app selector's length on the edge or row height: Settings fades away except
  that slider, and home shows underneath at the value under your finger. Let go to save it and bring
  Settings back. The typing ones show home as if you were typing, with suggestions (and the key bar,
  if it is on); the selector's row height shows its list open.
- **Hold the eye** (👁) at the top of Look & feel, Home screen, App selector, Log and Typing to see home with
  your settings as they are; let go to come back.

Home is only shown there: it takes no touches.

## The config command

Everything on the settings screen is a config key, also settable from the prompt (the full list is
in the [configuration reference](/reference/config/)):

```sh
config ls                    # every key with its value; * marks changed ones; tap a line to edit it
config get font.size
config set font.size 16      # 'set font.size 16' and 'config font.size 16' work too
config reset font.size
config reset all
```

Booleans take `on`/`off` (also `true`/`false`, `yes`/`no`, `1`/`0`). Numbers have a range and
choices a fixed list; an invalid value prints what is allowed. While you type `config set`,
suggestions offer keys and then valid values.

#+TITLE: Kolahal
#+SUBTITLE: A keyboard-first terminal launcher for Android

Kolahal (=io.github.rscipher001.launcher=) is a terminal-style home screen with first-class work
profile support and scripts in *Lua 5.4* or *JavaScript (QuickJS)*.

* Documentation

The full documentation (guides, command and config reference, scripting API) is at
https://rscipher001.github.io/kolahal/. Its source is in =docs/= (Astro + Starlight), deployed to
GitHub Pages by =.github/workflows/docs.yml= on pushes to =main= that touch =docs/=. To work on it
locally:

#+begin_src sh
cd docs && npm install && npm run dev    # http://localhost:4321/kolahal/
#+end_src

* Features

- Terminal home screen ::
  - Type a command or any part of an app name. Enter launches the best match, which is the
    highlighted first suggestion chip.
  - With an empty prompt, the strip shows your most-used apps, ranked by frecency. The strip is
    hidden until you start typing (=suggestions.auto off= keeps it visible).
  - Suggestions are a list stacked above the prompt, best match at the bottom nearest your thumb,
    with each command's short description (=suggestions.style chips= brings back the chip strip).
  - App selector (=selector.rail=) on the right edge while the keyboard is down: touch the edge
    and a panel with all your apps (favourites first, then A–Z) slides in. Slide your thumb along
    the edge to glide smoothly through the whole list, with the app under your finger magnified;
    slide left onto one and lift to launch, or hold on it for its actions. No keyboard needed.
- Profiles ::
  - Personal, work (managed profile), Android 15+ private space and clone profiles appear together.
  - Apps are tagged =[W]= / =[S]= / =[C]= in their own colours. =[P]= is shown only when the same
    app also exists in another profile.
  - Apps in a paused profile are faded. Opening one offers to resume the profile and launch the
    app in one tap.
  - The header shows the work state; tapping it resumes, or asks for a second tap before pausing.
- Readable log ::
  - Each command and its output form a block with a coloured gutter (scripts and errors have their
    own colours), and output older than the latest command is dimmed.
  - Day separators and right-aligned times. Wrapped lines indent past their prefix.
  - Fresh screen (=log.fresh=, 10 min): back on home after a while, it starts clean; one tap shows
    the earlier output. A ↓ button jumps to the newest lines; the header stays clear of the camera
    cutout even in full screen.
  - =help=, =config= and =script ls= render in two columns; =apps= is a grid of tappable chips.
- Touch ::
  - A two-row key bar (=ESC / - ⇤ ↑ ⇥ ⌫= and =TAB  It shows only while the on-screen keyboard is up
    for the prompt; the ⌨ button at the end of the prompt line turns it on or off (=keybar.auto off= keeps it always visible). =keybar.height= and =prompt.height=
    make both slimmer while typing. =log.lineheight= and =chips.height= tighten log lines and
    suggestion chips.| . ← ↓ → ⏎=); arrows and backspace repeat
    when held, and dragging sideways moves the cursor.
  - Tap any line for its main action; long-press opens an action sheet. Swipe a line right to copy
    it, left to delete it (with undo). Tap =$= on the prompt for the quick sheet (settings, battery,
    profiles, widgets, lock…) within thumb reach.
  - Pinch the log to resize text, swipe down on the header for notifications, tap empty space for
    the keyboard.
  - Gestures (Settings → Gestures, or =config set gesture.*=): double-tap empty log space locks the
    screen (optional accessibility service that only locks; =setup= → Double-tap to lock), swipe
    down on the header pulls the shade, swipe up on the prompt shows the app grid. Each can be
    =lock=, =shade=, =none= or any command. =lock= and =shade= are also commands.
- Header :: Large clock and date, then unlocks, battery, network, next alarm, profile state and
  ⚙ (settings). Every item is tappable. Items are icons (a battery drawn to its level, Wi-Fi / mobile /
  offline, unlocks, alarm, work / private); =header.icons off= shows text labels instead. Scrolling back through older output hides it entirely; scrolling
  toward the newest lines or running a command shows it as one line (time, battery, status count) so the log gets the room; tap or swipe down on it, press Home or
  come back from an app to expand it (=header.autohide=).
- Unlock counter :: Uses UsageStats =KEYGUARD_HIDDEN= events when Usage Access is granted, with an
  =ACTION_USER_PRESENT= fallback. =unlocks 7= shows the last week.
- Scripts ::
  - Timers by interval (=every 30m=) and/or daily times (=at 08:00,18:30=), with optional
    notifications.
  - Scripts marked =@command= become terminal commands that take arguments.
  - Event triggers: =@on unlock=, =@on charger= … run a script when something happens on the device.
  - Each run gets a =── hn · 22:40 ──= header and a stable per-script colour; lines that arrived
    while you were away are marked =•= under a "N new since you left" divider.
  - =status(text)= pins a line into the header.
- GUI screens ::
  - *Settings* (=settings= or ⚙): Material 3 Expressive grouped lists with switches, connected button
    groups, sliders, theme preview cards and backup export/import. Colours follow the terminal theme,
    or the system (Material You) colours with =gui.colors system=.
  - *Script manager* (=scripts=): import =.lua= / =.js= files from the file manager, create, run,
    edit, export and delete scripts, and set timers and notifications.
- Notifications :: With notification access (=setup= → Notification access), new notifications
  appear in the log in their app's colour. Tap opens the notification, long-press dismisses it or
  mutes the app. =notifs= lists active ones; =notifs mute <app>=, =notifs log off=.
- Media :: With notification access, =media= shows what's playing (app, title — artist, state,
  position / duration); =media play|pause|toggle|next|prev|stop=, or =mp= (play/pause), =next=,
  =prev=. The header shows "♪ Title — Artist" under the clock (=header.media=): tap toggles
  play/pause, long-press or ⏭ skips. It hides 30 minutes after playback was paused; the compact
  header shows a ♪ while something plays.
- Device toggles :: =torch [on|off]=, =volume [0-100|up|down|mute]=, =ring [normal|vibrate|silent]=,
  =dnd [on|off|alarms|none]=, =brightness [0-100|up|down|auto]=, =rotate [on|off]=,
  =screen-timeout <30s|1m|…>=; =wifi=, =bt=, =nfc= and =data= open the system panel (Android doesn't
  let apps switch radios). =toggles= lists everything; tap a line to change it. Silent / DND need Do
  Not Disturb access and brightness / rotate / timeout need "Modify system settings"; without them
  the command prints a tappable line that opens the grant page (also in =setup=).
- Feeds :: Built-in RSS/Atom subscriptions with unread counts, per-feed intervals and optional
  notifications: =feed add <url>=, =feed= (list), =feed read [id]=, =feed open=, =feed every 1 2h=.
  =feeds= opens the feed manager screen: add feeds, read items (tap opens the link and marks it
  read), per-feed refresh / notifications / interval, and OPML import / export.
- Widgets :: Host any app's home-screen widgets (work-profile ones too). =widgets= opens the
  Widgets page (also in Settings): add from a picker grouped by app with previews and sizes,
  long-press to move, resize in 48dp steps, remove, or place on home. Home widgets sit directly under
  the header and fold away with it while the log is in use (=widgets.home=, max height
  =widgets.height= 180dp). =widgets ls= lists them; =widget add [home]= opens the picker. Backups
  keep the layout; restored widgets get a one-tap "Add again".
- People :: =call <name>= / =sms <name> [text]= with contact suggestions (favourites first);
  =contacts [query]=. Numbers in the log are tappable.
- Favourites :: =pin <app>= (or long-press → Pin) puts an app first in the empty-prompt strip, in pin
  order, ahead of the most-used ones. =pins= lists them, =unpin <app>= removes one.
- Productivity :: =todo buy milk= / =todo= (tap ticks an item; long-press edits or deletes;
  =todo done 2=, =todo clear=; the header shows the open count, =header.todo=). =note <text>= and
  =notes [grep <q>|rm <n>]= (tap copies). =remind 10m tea=, =remind tomorrow 9:00 call mom=,
  =remind fri 8am …= post a notification on time and survive reboots; =reminders=, =remind rm <n>=.
  =timer 25m focus= and =alarm 7:30 gym= hand off to the clock app. =agenda [days]= lists upcoming
  calendar events by day (tap opens one; asks for the calendar permission on first use).
- App shortcuts :: =shortcuts <app>= lists an app's launcher shortcuts; =open maps:home= starts one.
  They are also in every app's long-press sheet.
- Instant launch :: With =launch.instant apps= (default) an app opens the moment the input matches only
  one app: =grov= opens Grove, =grow= opens Groww, without Enter. =launch.instant all= also runs
  argument-free commands and aliases that way (=setti= opens settings) and makes tapped history lines run at once.
  Calls, messages, uninstall, profile switches, =clear= and other sensitive commands always need
  Enter, and calls still open the dialer for you to confirm. =launch.instant.min= sets how many
  letters to type first (2).
- Calculator & units :: === 2^10=, === 5 km in mi=, === 72 f to c=, === 100 usd in eur= (rates cached
  for six hours).
- Web :: =search=, =yt=, =wiki=, =maps=, =play=; the engine is =config search.engine= (ddg, google,
  bing, brave, startpage) or a custom =search.url= containing =%s=.
- App events :: Installs, updates and uninstalls appear in the log (=log.packages=); an update, or an
  uninstall followed by a reinstall within 45 s, is one "updated" line. =installs [n]= lists the history.
- Screen time :: =usage [days]= shows time per app (needs Usage Access).
- Script library :: 15 ready-made Lua/JS scripts (weather, Hacker News, battery log, …) in the
  script manager's Library section, or =script lib= / =script install <name>=.
- Log history :: Scrolling to the top loads older entries; entries older than =log.keepdays= (60)
  are trimmed. =clear history= forgets the ↑ history but keeps the log.
- Widgets page :: Swipe sideways on home for a page of widgets (=widgets.page left|right|off=).
- Full screen :: Settings → Look & feel → Full screen (=config set statusbar hide=) hides the status bar;
  =immersive= hides the navigation bar too. Swipe from the edge to peek at them.
- Themes :: green, amber, mono, dracula, solarized, gruvbox, gruvbox-material.
- Fonts :: =font= switches the terminal font (log, prompt, header, suggestions, key bar, editor):
  the system monospace or the bundled JetBrains Mono, Fira Code, IBM Plex Mono and Source Code Pro
  (all SIL Open Font License 1.1; licence texts in =app/src/main/assets/licenses/=). =font import=
  (or the settings screen) loads your own .ttf/.otf (up to 10 MB) as =custom=.
- Hardware keyboard ::
  - Prompt: =↑/↓= history, =Tab= complete, =Esc= clear, =Enter= run, =Ctrl+L= clear screen,
    =Ctrl+U= kill line, =Ctrl+A/E= start/end.
  - Editor: =Ctrl+S= save, =Ctrl+R= run, =Ctrl+Z= / =Ctrl+Shift+Z= undo/redo, =Ctrl+F= find,
    =Ctrl+H= replace (=Enter= / =Shift+Enter= or =F3= / =Shift+F3= next/previous), =Ctrl+G= go to
    line, =Tab= accepts the first API/keyword suggestion, =Esc= closes the find bar, then (like Back)
    saves and closes. The strip above the keyboard suggests API members (=http.=, =rss.=, …) and
    keywords; a dim bar shows the signature of the call under the cursor, and =[?]= lists the full API.

Output can be filtered like a shell: =help | grep feed=, =history | tail 5=, =feed read | grep -v ad | head 3=,
=contacts | count= (filters: =grep [-v]=, =head n=, =tail n=, =sort [-r]=, =uniq=, =count=).

Anything that isn't a command, alias or script command is matched against app names. A mistyped
command gets a tappable "did you mean".

* Scripts

=script new hn= creates =hn.lua= from an RSS template. Use =script new feed.js= for JavaScript and
=--cmd= for a command template, or create scripts in the script manager. Both engines expose the
same API:

| Call                                                  | Result                                                                 |
|-------------------------------------------------------+------------------------------------------------------------------------|
| =log(text, ctx?)=                                     | Appends a line. =ctx.url= makes it a tappable link; other keys are kept. |
| =notify(title, body, ctx?)=                           | Notification if enabled for the script; =ctx.url= opens on tap.        |
| =status(text)=                                        | Pins one header line for this script; =status(nil)= clears it.         |
| =http.get(url, headers?)=                             | ={ status, ok, body, headers }=                                        |
| =http.request{ url, method, body, contentType, headers }= | Same as =http.get=; a table body is sent as JSON.                     |
| =rss.fetch(url)= / =rss.parse(xml)=                   | ={ title, link, items = [{ title, link, id, date, summary }] }=        |
| =rss.fresh(url)=                                      | Only items not returned before; marked seen only if the run succeeds.  |
| =store.get(k)= / =store.set(k, v)=                    | Persistent per-script strings.                                         |
| =http.cached(url, seconds)=                           | GET, reusing this script's stored response while it is fresh.          |
| =clipboard.get()= / =clipboard.set(text)=             | =get= is usually nil in timers (only the focused app may read it).     |
| =device.battery()=                                    | ={ level, charging }=                                                  |
| =device.network()= / =device.unlocks()=               | ="wifi"=, ="cell"=, ="eth"=, ="offline"= / today's unlock count.       |
| =apps.list()=                                         | =[{ label, pkg, profile }]=                                            |
| =notifications.recent(n?)=                            | =[{ pkg, app, title, text, time }]=, newest first (notification access). |
| =launcher.run(command)=                               | Runs a terminal command; only when the script is run from the prompt.  |
| =sleep(ms)=                                           | Up to 5000 ms (=await sleep(ms)= in JS).                               |
| =json.encode= / =json.decode=                         | Lua only (JS has =JSON=).                                              |
| =args=, =argline=                                     | Arguments when run as a command.                                       |

In JS the network calls are =async= (=await http.get(...)=, and =Promise.all= works). Lua calls
block, since scripts never run on the UI thread. A script's return value is printed. When a script
fails, tapping the error opens the editor at the failing line.

#+begin_src lua
-- weather.lua  (script new weather --cmd)
-- @command
-- @desc current weather: weather [city]
local city = argline ~= "" and argline or "London"
return (http.get("https://wttr.in/" .. city .. "?format=3").body:gsub("%s+$", ""))
#+end_src

** Event triggers

Besides timers, a script can run when something happens. Add one or more =@on= lines
(=-- @on unlock= in Lua, =// @on charger, unplug= in JS; commas or spaces separate events):

| Event          | When                                                     | =event= fields                     |
|----------------+----------------------------------------------------------+------------------------------------|
| =unlock=       | The device is unlocked (user present)                    | =name=                             |
| =charger=      | Power connected                                          | =name=, =level=, =plug= (ac/usb/wireless) |
| =unplug=       | Power disconnected                                       | =name=, =level=                    |
| =wifi=         | The default network becomes Wi-Fi                        | =name=, =network=                  |
| =offline=      | No network left                                          | =name=                             |
| =notification= | A notification reaches the feed (needs notification access) | =name=, =app=, =pkg=, =title=, =text=, =time= |
| =boot=         | First launcher start after the phone boots               | =name=, =uptime= (seconds)         |
| =headset=      | A wired headset is plugged in                            | =name=, =type=, =device=, =mic=    |

The payload is the global =event= (=event.name=, =event.level=, …); it is =nil= in Lua and =null=
in JS when the script runs from a timer, the prompt or the Run button. Only enabled scripts are
triggered, event runs are non-interactive (no =launcher.run=), and the same script + event runs
at most once every 30 seconds (=notification=: once per app every 30 seconds). Triggers are
received while the launcher process is alive, which as the home app is nearly always.
=script triggers= lists subscribed scripts, =script ls= and the script manager show them, and
the library's =charge-reminder= is a worked example.

#+begin_src lua
-- @on notification
if event.pkg == "com.whatsapp" and (event.text or ""):find("urgent") then
  notify(event.app, (event.title or "") .. ": " .. event.text)
end
#+end_src

* Moving scripts and settings between devices

- Backup file :: /Settings → backup → export…/ writes =kolahal-backup.json= with everything:
  changed settings, aliases, hidden/renamed/pinned apps, every script with its code and timers, and
  under =data= todos, notes, reminders, feeds (with read state), script stores, the log and
  launch/unlock history. Importing replaces that data and restarts the launcher. Edit it on a computer
  and use /import…/ to load it back on any phone.

  #+begin_src json
  { "kolahal": 1,
    "config":  { "theme": "gruvbox-material", "log.spacing": "16" },
    "aliases": { "m": "open maps" },
    "apps":    { "hidden": [], "labels": {} },
    "scripts": [ { "name": "hn", "lang": "lua", "code": "...", "every": 30,
                   "at": ["08:00"], "notify": true, "enabled": true } ] }
  #+end_src

- Single files :: /Script manager → import files…/ picks one or more =.lua= / =.js= files. The file
  name becomes the script name, and importing again updates the script. /export…/ on a script
  saves it as a file.
- Folder sync :: =script dir= picks a folder; =script export= / =script import= sync every script
  plus a =kolahal.json= with their timers.

* Architecture

#+begin_example
MainActivity (HOME) ── TerminalViewModel ── CommandProcessor
   screens: Terminal · Settings · Scripts · ScriptEditor
                               │
        AppRepository (LauncherApps, all profiles) + AppPrefs (hidden, labels, frecency, aliases)
        UnlockCounter · DeviceStatus · Config · Backup
        LogRepository / ScriptRepository / KvStore (SQLite, WAL)
                               │
        ScriptScheduler ──► WorkManager ──► ScriptWorker   [process :script]
                                             ├─ LuaEngine (LuaJava, Lua 5.4 native)
                                             └─ JsEngine  (quickjs-kt, QuickJS)
                                                   └─ HostApi (http, rss, log, notify, store, status)
#+end_example

- Isolation :: Scripts run in a separate =:script= process (=RemoteCoroutineWorker=), so a native
  engine crash can't take down the home screen. Results come back through the shared database plus
  a package-scoped broadcast.
- Lua sandbox ::
  - Fresh state per run. =java=, =io=, =package=, =require=, =debug=, =dofile=, =loadfile= and
    process-level =os= functions are removed, and only text chunks can be loaded.
  - An instruction-count hook, also installed on coroutines, enforces the 60 s timeout and a 64 MB
    memory cap. =pcall=, =xpcall= and =coroutine.resume= can't swallow either.
  - If a C function outlives the deadline, a watchdog kills the =:script= process.
- JS sandbox :: QuickJS with only the bindings above, a 64 MB memory limit and an evaluation timeout.
- Scheduling ::
  - Interval jobs are periodic work, with Android's 15-minute minimum.
  - Each daily time is a 24 h job anchored to its next occurrence. It is re-anchored on launcher
    start only when it drifted, and never while running or overdue.
- UI work :: One serial IO dispatcher with an exception handler, so a failed action is logged
  instead of crashing home. Log rows are pre-built off the main thread and rendered as immutable
  rows with cached text.

* Build

#+begin_src sh
./gradlew :app:assembleDebug              # debug APK ("Kolahal debug", package suffix .debug)
./gradlew :app:assembleRelease            # R8-optimised; signed with keystore.properties or the debug key
./gradlew :app:testDebugUnitTest          # JVM tests
./gradlew :app:connectedDebugAndroidTest  # engines, sandbox, timeouts, :script process, commands
#+end_src

- Toolchain :: AGP 9.1, Gradle 9.3.1, Kotlin 2.3.20, compileSdk 37, targetSdk 36, minSdk 28,
  Jetpack Compose. Material 3 is pinned to =1.5.0-beta01= for the Expressive components; 1.5.0 stable
  isn't released yet (checked 2026-10-17), switch =material3= in =gradle/libs.versions.toml= when it is.
- Baseline profile :: =app/src/release/generated/baselineProfiles/= is generated by the
  =:baselineprofile= module (cold start, typing, help/apps output, log scroll, settings). Regenerate
  with an emulator attached: =./gradlew :app:generateReleaseBaselineProfile=.
- Signing :: Optional =keystore.properties= keys: =storeFile=, =storePassword=, =keyAlias=,
  =keyPassword=.
- Use the release build day to day :: Debug Compose builds are noticeably slower to scroll.
- Compile after sideloading :: A sideloaded APK runs without ahead-of-time compilation until Android
  compiles it during idle maintenance, so it can feel laggy at first. To compile it immediately, run
  =adb shell cmd package compile -m speed -f io.github.rscipher001.launcher=.
- After installing :: Run =setup=. It checks the default launcher, Usage Access, notifications and
  battery optimisation, and each unchecked line fixes itself when tapped.
